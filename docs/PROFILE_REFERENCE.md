# Profile reference

INI syntax: `[section]`, `key = value`, `#`/`;` full-line comments, inline comments start with
whitespace + `#`. Repeatable keys append. Section/key names are case-insensitive. Unknown names are errors.
Booleans: `yes/no/true/false/on/off/1/0`. Variables: `$HOME $USER $UID $GID $XDG_RUNTIME_DIR $STATE $CWD $ARCH`, `~/`.
Mount syntax: `SRC` or `SRC => DEST` (DEST defaults to SRC). Globs (`* ? [..]`) are allowed in `[fs]` sources.

## [profile]
| key | default | meaning |
|---|---|---|
| name | file stem | `[a-z0-9][a-z0-9_-]{0,31}`; names state dirs and the netns |
| description | | shown by `list` |
| mode | `host` | `host` (whitelist host binaries/libs) or `bundle` (private Alpine) |
| os | | `data/os/NAME.profile`. **Bundle profiles: required**, names the shared Alpine userland (version, pinned hash, packages). Host profiles: optional pin of the OS lock to use; default is the entry matching the host's `/etc/os-release`. |
| command | | argv, shell-style quoting; replaced by `-- CMD…` on the CLI |
| hostname | `holdfast` | UTS hostname inside |
| terminal | `filter` | `filter`: when stdin/stdout are terminals the program runs on a fresh pty (its own controlling tty) and everything it prints is filtered, see "Terminal filter" below. `passthrough`: the sandbox writes straight to your terminal (not recommended). |
| new_session | `yes` | `bwrap --new-session`. Only used when the terminal is NOT proxied (`terminal = passthrough`, or stdio is not a tty). It blocks TIOCSTI, but Ctrl-C then hits holdfast and `/dev/tty` is unavailable. With `terminal = filter` it is unnecessary. |
| disable_userns | `yes` | `--disable-userns` when bwrap ≥ 0.8: nothing inside may create user namespaces, which also removes a large kernel attack surface. Browsers probe for them to build an inner sandbox; Firefox/LibreWolf then print one harmless line (`CanCreateUserNamespace() ... ENOSPC`) and continue without that layer, keeping their seccomp filter. `MOZ_ASSUME_USER_NS=0` in `[env]` only silences that line. `no` allows the inner namespace layer, at the price of user namespaces being possible inside this sandbox |
| seccomp | `default` | `default` (built-in libseccomp filter, see below) · `none` (no filter, warns) · path to a compiled BPF file. A build without libseccomp refuses `default`. |
| cwd | `ask` | `none` / `ask` (tty prompt) / `yes`; mounts the current dir at `cwd_dest` |
| cwd_dest | `/shared` | absolute, not under `/usr /etc /bin /lib /proc /dev /sys /run /var` |

## [bin]  (host mode)
`allow = name [name=/abs/path …]` – each is bound at `/usr/bin/<name>`. Missing binaries are skipped with a warning.

## [fs]
| key | meaning |
|---|---|
| ro / ro_try | read-only bind (`_try`: skip if absent) |
| rw / rw_try | read-write bind (refused under system prefixes) |
| tmpfs | extra tmpfs mount |
| deny | extra deny-list path (globs ok) |
| defaults | `yes`: bind ld.so.cache, terminfo, zoneinfo, os-release and the CA trust store read-only (`/etc/ssl`, `/etc/ca-certificates`, `/usr/share/ca-certificates`, `/etc/pki`, `/usr/share/p11-kit`; the ones your distro has), plus resolv.conf if networked |
| libs | `minimal` (default): bind exactly the locked files of the libs named in `[libs] use` (below); nothing is analysed at run time. `full`: bind `/usr/lib /usr/lib64` (and `/lib*`) read-only; needed for toolchains (`gcc`, `rustc`, ...) and for browsers. |

## [libs]  (host mode, `libs = minimal`)
`use = name …` (repeatable) – the `data/lib/NAME.profile` definitions this profile needs (`base` is implicit). Every `[bin] allow`
command must be listed in some used lib's `commands`, otherwise the profile is rejected.
Profiles contain **no paths**: the concrete files come from the locked section of the matching `data/os/*.os`
(`[profile] os = NAME`, or detected from `/etc/os-release`), generated by `holdfast libs --refresh` and verified by
`holdfast libs --check`. Format, workflow and the resolution steps are in `docs/DATA.md`.

## [home]
`user` (fake login name, default `sandbox`) · `dirs` (create in fake home) · `bind = REL [=> REL]` (rw, from real `$HOME`) · `ro_bind` (same, read-only).
The fake home is persistent at `<data>/profiles/<name>/home`.

## [env]
`set = NAME=VALUE` · `pass = NAME …` (copy from host; `TERM LANG COLORTERM` always) · `unset = NAME …`.
The environment is otherwise cleared.

## [network]
`mode = none|pasta|host|ivpn` · `dns` (pasta) · `wg_conf` (ivpn) · `ns_name` (default `hf-<name>`) · `subnet` (1-254, default derived) · `verify = yes|no`.

`pasta`: private network namespace with outbound internet via `pasta` (package `passt`). Host loopback services and
inbound ports are unreachable, and host *abstract* unix sockets (X11, D-Bus) are not shared. `host` shares the host
network namespace and therefore those sockets: prefer `pasta`. The LAN is reachable in both.

`dns` (**required** with `mode = pasta` and `mode = host`; `--dns=` on the command line overrides it). The host's
`/etc/resolv.conf` never enters a sandbox unless you ask for it:
- `pasta`: an IPv4 address. pasta forwards the sandbox's queries to it (`--dns-host`); the sandbox's `/etc/resolv.conf`
  points at pasta's forwarder. pasta itself still opens the host's resolv.conf at startup and may print "Couldn't get any
  nameserver address"; that is harmless, because what it reads there is not used.
- `host`: an IPv4 address (written to the sandbox's `/etc/resolv.conf`), or `dns = host` to mount the host's file.
- `ivpn` takes DNS from the WireGuard config and `none` has no network: `dns` there is an error.

Deps and the userland install steps do not use this key; they use the os file's `[install] dns`. The two are separate
on purpose: `[network] dns` is what the *program* resolves with on every run, `[install] dns` (in `data/os/NAME.profile`) is
what downloading the userland, `apk add` and every dep with `[network] mode = pasta` use. A bundle profile with
`mode = pasta` therefore names a resolver in both places.

### Default seccomp filter
`seccomp = default` returns EPERM for: kexec/module/reboot, `bpf`, `perf_event_open`, `userfaultfd`, `io_uring_*`,
`keyctl`/`add_key`/`request_key`, `mount` and the new-mount API, `pivot_root`, `open_by_handle_at`, clock setting,
legacy x86 calls (`modify_ldt`, `iopl`, ...), plus the `TIOCSTI`/`TIOCLINUX` ioctls. `clone`, `clone3`, `unshare`,
`setns` and `ptrace` stay allowed (browsers, nested sandboxes, debuggers). Foreign-ABI syscalls are killed.

### Terminal filter
A terminal is programmable: bytes a program prints can set your clipboard (OSC 52), forge titles and hyperlinks, make the
terminal type replies into your shell (title/answerback reports) and leave mouse reporting on after a crash.
With `terminal = filter` the sandbox runs on a pty and its output goes through an allowlist parser. Passed: text, UTF-8,
colours (SGR), cursor movement, erase/scroll, alternate screen, mouse/focus/bracketed-paste/sync modes, safe queries
(DA, cursor position, XTVERSION, DECRQM, kitty keyboard, fg/bg colour query), charset designation, window titles
(sanitised and prefixed `[sandbox]`). Dropped: all other OSC (52 clipboard, 8 hyperlinks, 7, 9, 99, 777, 1337, colour
setting, ...), DCS/APC/PM/SOS (sixel, kitty graphics, tmux passthrough), XTWINOPS (`CSI t`: title reports, resize, move),
RIS, keyboard lock, media copy, 8-bit/C1 controls, ENQ and other C0 controls. When the sandbox ends, modes it left on are reset.
Not covered: what the program *draws* (it can still print misleading text), and bidi overrides in terminal output.
Input is relayed byte for byte. If the terminal ever stays raw after a hard kill of holdfast itself, run `reset`.

## [display]
| key | default | |
|---|---|---|
| use | | name of a display file in `data/display/` (`holdfast list displays`). Leave it out for no display at all |
| allow_host | `no` | consent when that display is `server = host`: the sandbox then shares your real session (X11: it can see and drive all your windows; Wayland: it becomes a client of your compositor, which may offer it privileged extensions). Consent lives here, not in the shared display file. An error with a nested display or no display |

What the display *is* (server, window size, window manager, cookie) is described once in `data/display/NAME.profile`, see `docs/DATA.md`.
The old `protocol`, `mode`, `size`, `wm`, `xauth`, `allow_host_x11` and `allow_host_wayland` keys are errors here, with a message that says so.

## [gpu]
| key | default | |
|---|---|---|
| mode | `none` | `none` / `render`. `render` is itself the consent: bind DRM render nodes (`/dev/dri/renderD*`) so Mesa can use the GPU. Nothing is bound without this key, and `[display]` never implies it |
| device | every render node found | optional, repeatable: bind only these nodes, e.g. `device = /dev/dri/renderD128`. Only `/dev/dri/renderD<number>` is accepted; `card*`, `/dev/nvidia*` and anything else are refused (exit 3) |

`mode = render` applies to host and bundle profiles. A bundle needs the Mesa drivers in its userland (`mesa-dri-gallium` on Alpine);
a host profile with `libs = minimal` needs a `data/lib` definition that provides the GL/EGL/gallium files (a `libs = full` profile
already works). holdfast sets **no** Mesa variables: do not force `LIBGL_ALWAYS_SOFTWARE` in a profile that wants GPU rendering.

The shipped demo `gpu-xephyr` (`data/profile/gpu-xephyr.profile` + `data/display/x11-xephyr-glamor.profile`) shows the two halves
together: `[gpu] mode = render`, Xephyr started with glamor, and `glxinfo -B` as the command. Use it to check which renderer this
host actually provides before copying the keys into a real profile; `holdfast doctor` reports render nodes, drivers and whether
your Xephyr advertises `-glamor`.

The render node exposes the host kernel's GPU driver to the sandbox. GPU drivers are large and have had local privilege-escalation
bugs; GPU memory isolation is the driver's, not holdfast's. This is why the default is `none`, only render (not modesetting) nodes
are offered, and the node must be openable read-write by your user (`render`/`video` group or a logind ACL). NVIDIA's proprietary
driver needs the host's glibc userspace and is not supported in a musl bundle; nouveau/NVK works through the same render node.

## [audio]  `mode = none|pulse` – pulse also grants microphone access.
## [clipboard]  `mode = none|out` · `path` (in-sandbox file, default `/tmp/clip_pipe`) · `sanitize = yes|no` (default `yes`: strip control characters, incl. ESC/CR/DEL/C1 and bidi overrides; `\n` and `\t` are kept).
## [git]  `protect = yes|no` – re-bind every `.git` read-only under the mounted tree.
## [fonts]  `allow = family …` – substring match on font file paths; only these are visible.

## [deps]  (bundle mode)
`use = name …` (repeatable) – the `data/dep/NAME.profile` install recipes for this profile, run in this order. Each recipe runs
once as an ordinary run of this profile (its userland read-only, its `$HOME`, your uid, its seccomp and terminal filter) with
only the network and the command taken from the recipe, and is stamped on its own: a newly added dep installs on the next run;
an edited recipe is refused until `holdfast run --refresh-dep=NAME PROFILE` runs that recipe again (`--refresh` runs all of
them and rebuilds a changed userland). A dep whose `provides` files are gone from `$HOME` runs again by itself. The recipe's `os` must equal this
profile's. A host-mode profile cannot use deps. Format, the exact list of overrides and `needs`: `docs/DATA.md`.

## Bundle mode: where the rest went
There is no `[bundle]` section any more. The inline `provision` lines became `data/dep` recipes (`[deps] use`), and the userland
itself (`alpine_version`, `alpine_mirror`, `alpine_sha256`, `packages`) lives once in `data/os/NAME.profile` (`kind = bundle`);
profiles say `os = NAME`. Every profile naming the same file shares one rootfs under `<data>/bundles/NAME`. There is no setup
command: the first `run` creates it (inside sandboxes) and later runs verify it was built from the current file;
`holdfast run --refresh PROFILE` rebuilds it if its definition changed. The old keys are errors that point here.
